# RepoTap v1.2.0 — GitHub Login, DSA Sheets & Streak Dashboard

## Goals
1. Replace manual PAT entry with **GitHub OAuth login** (auto token generation).
2. Bundle **3 DSA sheets** (Blind 74, Striver 150, NeetCode 150) with progress tracked **automatically from accepted LeetCode submissions** (+ manual toggle fallback).
3. **Daily streak** based on accepted solutions + commits.
4. New **Dashboard tab** in the popup showing streak, activity, and per-sheet progress.

## Decisions (confirmed with user)
- OAuth only; remove PAT input from Settings. Existing `rt_settings.githubToken` is respected (treated as logged-in, shows "Disconnect").
- Sheet progress: auto-match by LeetCode `titleSlug` from accepted submissions; manual checkbox override available.
- Streak counts days with >=1 accepted solution or commit.
- Dashboard as a new top-level popup tab.

## 1. GitHub OAuth login (auto token generation)

### 1.1 One-time setup (outside code)
1. Register a GitHub OAuth App at https://github.com/settings/developers → "OAuth Apps" → New:
   - Homepage: extension repo URL
   - **Authorization callback URL**: `https://<extension-id>.chromiumapp.org/` (ID is visible at `chrome://extensions` after loading unpacked)
2. Put the resulting **client_id** into `src/lib/auth/config.js` (single constant `GITHUB_CLIENT_ID`). No client secret needed — GitHub allows secret-less code exchange when the redirect URI is a non-web-app URI like `chromiumapp.org`.

### 1.2 Flow (`src/lib/auth/github-auth.js`, new)
- `login()`: `chrome.identity.launchWebAuthFlow({ url: https://github.com/login/oauth/authorize?client_id=…&scope=repo&redirect_uri=https://<id>.chromiumapp.org/, interactive: true })` → extract `code` from redirect URL.
- Exchange: `POST https://github.com/login/oauth/access_token` with `code` (+ `Accept: application/json`), no secret → `access_token`.
- Verify: `GET https://api.github.com/user` with the token → `login`, `avatar_url`.
- Persist to `rt_settings`: `githubToken`, `githubLogin`, `githubAvatarUrl`, `authMethod: 'oauth'`, `authedAt`.
- `logout()`: clears those fields (GitHub user-to-server revocation needs the client secret, which extensions can't keep secret — token stays valid upstream; documented limitation, same as most extensions).
- Called from popup Settings via a message to the service worker (`LOGIN_GITHUB` / `LOGOUT_GITHUB` / `GET_AUTH_STATE`), so the popup doesn't need `identity` in an extension-page context (launchWebAuthFlow works from both, but SW keeps auth logic in one place).
- `scope=repo` keeps parity with current behavior (private repos allowed).

### 1.3 Manifest changes
- `permissions`: add `"identity"`.
- `host_permissions`: add `"https://github.com/*"` (auth + token endpoints).
- Bump version to `1.2.0`.

### 1.4 github.js
- No change needed (`commitToGitHub` already reads `settings.githubToken`). Add `getAuthenticatedUser()` helper for the Settings UI badge.

## 2. Streak + activity tracking

```
rt_activity = { "2026-11-17": { accepted: 2, commits: 1 }, … }
```

## 3. DSA sheets

### 3.1 Data files (new, `src/data/sheets/`)
Bundled static JSON, keyed by LeetCode `titleSlug` (the same slug used in problem URLs the content scripts already capture):
- `blind74.json` — the classic Blind 75 list minus premium "Encode and Decode Strings" (free-only variant, 74 items).
- `striver150.json` — takeuforward "Striver's 150 – Master Patterns in DSA" (17 modules: Arrays 15, Hashing 6, Sliding Window & Two Pointers 8, Binary Search 11, Strings 5, Stack & Queues 10, Linked List 11, Binary Trees 11, BSTs 6, Heaps 6, Recursion & Backtracking 11, Greedy 6, Graphs 17, DP 20, Tries 3, Bit Manipulation 3, Math 1).
- `neetcode150.json` — NeetCode 150 (18 topics, 28E/101M/21H), verified against neetcode.io/practice.

Schema per sheet:
```json
{ "id": "neetcode150", "title": "NeetCode 150", "source": "https://neetcode.io/practice",
  "problems": [ { "slug": "two-sum", "title": "Two Sum", "difficulty": "Easy", "topic": "Arrays & Hashing" } ] }
```
Compiled once during implementation from the public pages (websearch results already give full NeetCode 150 ordering; Striver's from takeuforward prep-hub page; Blind 74 from the standard list). Non-LeetCode items (a few Striver entries are takeuforward articles) keep `slug: null` and are manual-check only.

### 3.2 Progress store (new key `rt_sheet_progress`)
```
{ "neetcode150": { "two-sum": { "solvedAt": "2026-11-17", "source": "auto" } }, … }
```
Helpers in `storage.js`: `getSheetProgress()`, `markSheetSolved(sheetId, slug, source)`, `unmarkSheetSolved()`, `setSheetManual()`.

### 3.3 Auto-detection
- Content scripts already capture accepted LeetCode submissions (`titleSlug` available in page-bridge / leetcode.js extraction). Ensure the `SOLUTION_ACCEPTED` payload includes `platform: 'leetcode'` and `titleSlug` (add if missing).
- Service worker on `SOLUTION_ACCEPTED`: for each sheet, if slug matches → `markSheetSolved(sheetId, slug, 'auto')`.
- **Backfill**: when Dashboard first opens (or on install/update), scan `rt_history` for LeetCode entries with a slug/title and mark them solved (`source: 'backfill'`).

### 3.4 UI (Dashboard tab)
- `src/popup/pages/Dashboard.jsx` + `src/popup/components/dashboard/` (StreakCard, ActivityStrip, SheetCard, SheetDetail, ProblemRow).
- App.jsx `page` state gains `'dashboard'`; Header nav gains a Dashboard item (icon + label, consistent with Commit/History/Settings).
- Dashboard layout:
  - **Streak card**: flame + current streak, best streak, last-7-days activity strip (accepted vs commit dots).
  - **Sheets overview**: one card per sheet — progress bar (solved/total), difficulty breakdown, topic chips.
  - **Sheet detail** (drill-in): problems grouped by topic, each row = checkbox (manual override) + title + difficulty badge + solved-date + link to LeetCode. Filter: All / Unsolved / by difficulty.
- Tailwind, dark-mode aware, matches existing component style.

## 6. Risks / notes
- OAuth App registration is a user action; plan includes the exact steps. Client_id is public (safe in extension code); never add a client secret.
- Extension ID changes if the unpacked path changes → callback URL must be updated (only matters pre–Web Store).
- GitHub user token revocation requires client secret; logout is local-only (industry-standard for extensions).
- Striver/NeetCode sheets are periodically revised; JSON gets a `sheetVersion` + `compiledAt` field so we can refresh later.
